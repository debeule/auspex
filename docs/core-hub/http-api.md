## Scope

core-hub's HTTP surface: the write token and CORS, which this file owns; the signal and watchlist endpoints; the dead-letter replay endpoint's place in that surface; error and value formats; actuator exposure; and the scheduled health reporter.

Not in this file: what a replay does ([consumption.md](consumption.md)); how corroborations are found and scored ([corroboration.md](corroboration.md)); the dashboard's server layer and login, which hold the token on the browser's behalf ([dashboard.md](../dashboard.md)); metric names and alert rules ([observability.md](../operations/observability.md)).

## Requirements

- <a id="HUB-041"></a>**HUB-041** — Every request under `/api` whose method is not GET or HEAD needs the header `Authorization: Bearer <CORE_HUB_WRITE_TOKEN>`. Without the header, with another value, or when no token is configured, core-hub answers 401 with a JSON error body and does not run the request. core-hub starts without a token configured, logs a warning, and then refuses every such request.
- <a id="HUB-042"></a>**HUB-042** — The token comparison takes the same time whatever the presented value (`MessageDigest.isEqual`).
- <a id="HUB-043"></a>**HUB-043** — core-hub returns no CORS headers; a browser reaches it only through the dashboard's server layer.
- <a id="HUB-044"></a>**HUB-044** — `GET /api/v1/signals/{ticker}` accepts only a ticker matching `^[A-Z][A-Z0-9.\-]{0,9}$` and answers 400 for any other, before a query runs.
- <a id="HUB-045"></a>**HUB-045** — For a valid ticker that no signal reaches, that endpoint answers 200 with empty lists.
- <a id="HUB-046"></a>**HUB-046** — That endpoint returns the direct signals of the companies carrying the ticker and the corroborations those signals take part in, each corroboration with its score (COR-013); superseded corroborations are left out.
- <a id="HUB-047"></a>**HUB-047** — The watchlist endpoints under `/api/v1/watchlist` are: list (`GET`); preview (`GET /preview?ticker=`), which upper-cases the ticker, resolves the company from the SEC ticker file and suggests trial conditions and interventions from ClinicalTrials.gov, the call recorded as the exception under [INV-4](../system/invariants.md#INV-4); add (`POST`), 201, or 409 when the ticker is already listed, after which company tickers are back-filled (HUB-034) and a back-fill failure is logged, never returned; delete (`DELETE /{ticker}`), 204; change gene targets (`PATCH /{ticker}/gene-targets`); and summary (`GET /{ticker}/summary`).
- <a id="HUB-048"></a>**HUB-048** — `POST /api/dlt/{topic}/replay` is a write under `/api` and needs the token (HUB-041); what it does is HUB-016.
- <a id="HUB-049"></a>**HUB-049** — Every error answer is a JSON body with a message and the HTTP status, never a stack trace.
- <a id="HUB-050"></a>**HUB-050** — Response timestamps are ISO-8601 in UTC with a `Z` suffix, and every `confidence_score` in a response is a number in [0, 1].
- <a id="HUB-051"></a>**HUB-051** — Actuator exposes only `health`, `info` and `prometheus`, under `/actuator`, outside `/api`; they are read-only and need no token.
- <a id="HUB-052"></a>**HUB-052** — A scheduled health reporter exports, at the interval set in `application.yml` (`auspex.health.report-interval-ms`): each dead-letter topic's depth, counted from the `corehub-dlt-replay` group's committed offset, or from the earliest retained record when there is no committed offset or it lies before that record; and each source's age of its latest signal, read from `signal_current` so it survives a restart. Metric names and the alerts that read them are in [observability.md](../operations/observability.md).
