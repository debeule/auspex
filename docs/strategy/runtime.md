# Strategy runtime

Domain: STR · Code: `services/strategy/src/auspex_strategy/runtime/`, `services/strategy/src/auspex_strategy/metrics/`, `services/strategy/src/auspex_strategy/__main__.py` · Last reviewed against: develop @ `b7582c3`

## Scope

How registered strategies run: the replay runner and the streaming runtime, decision isolation, input health, virtual books and their fills, overlap, latency and funnel bookkeeping, the runtime's state in MinIO, the strategy metrics and the runtime's HTTP surface and kill-switch command line. Settings are environment variables named in `.env.example` (`STRATEGY_TIMEOUT_SECONDS`, `HEALTH_CHECK_INTERVAL_SECONDS`, `PASS_THROUGH_POSITION_EUR`, `MIN_TRADES_FOR_METRICS`); this file names them and never copies their values.

The runtime's HTTP routes, the metrics API included, have no authentication, and no dashboard route reaches them yet: the dashboard's server layer has no strategy upstream ([dashboard.md](../dashboard.md)).

Not in this file: the strategy interface and as-of rules ([contract.md](contract.md)); the risk review itself ([risk.md](risk.md)); decision traces ([decision-trace.md](decision-trace.md)); the corroborated event's wire format and dead-letter naming ([contracts.md](../system/contracts.md)); fills and costs ([simulation.md](../research/simulation.md)); the container, its port binding and memory limit ([topology.md](../operations/topology.md)).

## Requirements

*Service boundaries.*
- <a id="STR-016"></a>**STR-016** — The strategy layer is its own service (`services/strategy/`, package `auspex_strategy`). It uses the backtesting package's market simulation as a path dependency and never copies it ([RES-065](../research/simulation.md#RES-065)).
- <a id="STR-017"></a>**STR-017** — All runtime state is in the `auspex-strategy` bucket under `strategy/`: books (`books/<strategy>/<mode>/trades.parquet`), funnel counts (`funnel/<strategy>/<mode>.json`), pauses (`health/pauses.jsonl`), latency (`latency/distribution.jsonl`), offset checkpoints (`checkpoints/<group>/<topic>.json`), traces (`traces/<strategy>/<mode>/traces.jsonl`), kill-switch flags and their event log (`killswitch/`) and catalyst holds (`risk/catalyst_holds.jsonl`). The runtime writes nothing to Postgres or Neo4j (applies [INV-2](../system/invariants.md#INV-2)).

*Replay and streaming.*
- <a id="STR-018"></a>**STR-018** — A replay runs every `research`-or-above strategy on the corroborations in time order, calling `decide()` inline. Each event's intents from `paper`-or-above strategies go to risk together, and approved ones trade only into `backtest` books, never into a forward book. A replay is deterministic, `intent_id`s included.
- <a id="STR-019"></a>**STR-019** — The streaming runtime consumes the corroborated topic ([CON-002](../system/contracts.md#CON-002), [CON-032](../system/contracts.md#CON-032)) in its own consumer group, `auspex-strategy-runtime`, and runs only `paper`-or-above strategies. It publishes to no topic. It never commits Kafka offsets: the MinIO checkpoint, saved after each event, is its resume position.
- <a id="STR-020"></a>**STR-020** — An unreadable corroborated payload never blocks its partition and never disappears without a dead-letter record (applies [INV-11](../system/invariants.md#INV-11)); dead-letter naming and headers are [CON-035](../system/contracts.md#CON-035) to [CON-037](../system/contracts.md#CON-037).
- <a id="STR-021"></a>**STR-021** — Re-processing an event after a restart books no second order for the same `intent_id`, and the live corroboration history and the daily-loss state survive a restart (applies [INV-10](../system/invariants.md#INV-10)).
- <a id="STR-022"></a>**STR-022** — A strategy that declares an input is paused while that input is unhealthy and resumes when it recovers. The runtime polls the per-input health every `HEALTH_CHECK_INTERVAL_SECONDS`; no answer, or an input missing from the answer, counts as unhealthy. Each pause start and end is recorded, and events skipped while paused are not counted as seen.
- <a id="STR-023"></a>**STR-023** — core-hub serves the per-input health the runtime polls, `GET /api/v1/health/inputs` answering `{"inputs": {"<input_source>": "UP" | "DOWN"}}`. The provider's contract belongs in [http-api.md](../core-hub/http-api.md).
- <a id="STR-024"></a>**STR-024** — A live corroboration record carries its ticker and its participants' source types.

*Execution.*
- <a id="STR-025"></a>**STR-025** — A crash, a call past `STRATEGY_TIMEOUT_SECONDS` or an invalid intent (not a list of intents, another strategy's name, an empty or disallowed ticker) is logged, counted against that strategy and discards its output for the event; it never reaches another strategy. The timeout applies in streaming only; a timed-out call keeps running in its thread and its result is discarded.
- <a id="STR-026"></a>**STR-026** — An order enters at the open of the first NYSE session after its `as_of` date; a live order stays pending until that session's bar is in the price snapshots. A position exits under `FixedDays` at the market simulation's exit price, or under `StopLossPct` at the first session the market simulation's stop fill triggers. Costs and the EUR conversion equal the market simulation's.
- <a id="STR-027"></a>**STR-027** — Book rows are append-only (`order`, then `open` or `rejected`, then `close`; a correction is a new offsetting row), and every row carries the `strategy_version` of the intent that placed the order, so a trade belongs to the version that opened it.
- <a id="STR-028"></a>**STR-028** — Intents from different strategies on the same event, ticker and direction are flagged on each other's rationale (`overlap_with`); an overlap is not a rejection.
- <a id="STR-029"></a>**STR-029** — The corroboration-to-intent latency is recorded per intent with its strategy and version, and the runtime warns at startup when the median exceeds a strategy's known-at delay.
- <a id="STR-030"></a>**STR-030** — Per strategy version and mode, the runtime counts the events `decide()` ran on, the intents produced and the intents risk approved.
- <a id="STR-031"></a>**STR-031** — All of an event's tradable intents go to one risk review ([risk.md](risk.md)); the intents of a strategy whose kill switch is on are dropped before risk.

*Metrics.*
- <a id="STR-032"></a>**STR-032** — Strategy metrics are computed on request from the books, funnel counts, latency log and price snapshots, and never stored. Each figure covers one strategy version in one mode. A summary reports the activity funnel (`inputs_seen`, `intents`, `passed_risk`, `filled`, `closed`), trade metrics, return metrics, the comparison with the same version's `backtest` book, and latency; a forward book's mean abnormal return outside that backtest's confidence interval sets `paper_tracking_deviation`.
- <a id="STR-033"></a>**STR-033** — Every metric group carries its sample size `n`. Below `MIN_TRADES_FOR_METRICS` closed trades, a required `.env` value, a group reports `insufficient_data: true` with null statistics, never a number.
- <a id="STR-034"></a>**STR-034** — A trade's abnormal return is the market-model CAR of [EVA-017](../research/evaluation-protocol.md#EVA-017) over sessions `[+1, +h]`, `h` the sessions from entry to exit, in the trade's direction, minus round-trip costs as a fraction of the entry notional.
- <a id="STR-035"></a>**STR-035** — The deflated Sharpe uses the per-trade Sharpe, skewness and kurtosis of those returns, with `n_trials` the trial count of the hypothesis's family ([EVA-011](../research/evaluation-protocol.md#EVA-011)), at least 1, read without taking the ledger's lock.
- <a id="STR-036"></a>**STR-036** — The correlation matrix is the Pearson correlation of abnormal returns across strategy versions, aligned on close dates; a version below the minimum sample is left out.
- <a id="STR-037"></a>**STR-037** — A trade with zero net P&L counts as a loss, not a win.
- <a id="STR-038"></a>**STR-038** — Drawdown is the largest fall of capital plus cumulative net P&L (EUR) from its running peak, in percent, with capital the largest allocation one position received.

*HTTP and command line.*
- <a id="STR-039"></a>**STR-039** — The runtime serves, on its own port (`STRATEGY_RUNTIME_PORT`): `GET /health` (status plus each strategy's failure count and pause state), `GET /metrics` (Prometheus), `GET /api/v1/metrics/strategies` (a summary per booked version and mode of every strategy not retired), `GET /api/v1/metrics/strategies/<name>/<version>` (404 when the version has no book) and `GET /api/v1/metrics/correlation?mode=<mode>`. Its host exposure is [OPS-005](../operations/topology.md#OPS-005).
- <a id="STR-040"></a>**STR-040** — The kill switch is set and reset from the command line (`python -m auspex_strategy kill`) without Docker, needing only the MinIO settings.

## Known traps

- A position opened with `ExitOnSignal` never closes: `PaperBroker` closes only `FixedDays` and `StopLossPct` positions (`services/strategy/src/auspex_strategy/runtime/broker.py`), and `## 2026-10-10 — Strategy runtime — CHOICE — state placement, timing and the pass-through stub` (item 3) records that no automatic exit exists yet.
- The kill-switch event log assumes one writer, but the command line and the runtime both append to it. Every JSONL append, in the kill switch and in `trace/store.py` alike, goes through `append_line` in `services/strategy/src/auspex_strategy/runtime/store.py`, a read-then-put whose docstring says the runtime is the only writer; a command-line trigger landing during a runtime append can lose one of the two lines.
- The compose comment on `HEALTH_CHECK_BASE_URL` in `docker/docker-compose.yml` says core-hub serves the per-input health; it does not yet (STR-023).
- The runtime's memory limit belongs to [topology.md](../operations/topology.md#OPS-014), not here.

## Rationale

- The runtime is a pure consumer: `## 2026-09-20 — Strategy layer session 2 — CHOICE — Event-driven Kafka consumer for the strategy runtime` keeps it off the Airflow schedule so it reacts as events arrive, and it may not publish a new topic, which is why it has no dead-letter topic of its own today (STR-020).
- Metrics are served from the runtime's own HTTP server rather than a new container because the runtime already holds the MinIO client, the prices and the config, and the memory budget has no room for another service (`## 2026-10-11 — Strategy metrics — CHOICE — where the spec left the metrics open`, item 7).
