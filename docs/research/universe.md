# Point-in-time universe

Domain: RES · Code: `services/backtesting/src/auspex_backtesting/universe/`, `services/backtesting/src/auspex_backtesting/backtest/membership.py`, `services/backtesting/dags/universe_build.py`, `services/backtesting/scripts/build_universe.py` · Last reviewed against: develop @ `b7582c3`

## Scope

The monthly lists of companies a backtest may trade: which rules file defines a universe and how it is locked, what a company must show to be admitted on a rebalance date, listing spans, exits and tickers, what the build stores, the backfill scope it exports, and how it reads SEC.

Not in this file: how a backtest uses the lists, the windows the prices do not cover, the delisting bound and the survivorship flag ([backtesting.md](backtesting.md)); the price snapshots it reads ([market-data.md](market-data.md)); SEC's access rules ([connectors.md](../ingestion/connectors.md)); the SEC request budget across containers and the DAG schedule ([orchestration.md](../operations/orchestration.md)).

## Machine-readable authorities

- `config/universe/rules.yaml` — the biotech universe: `version`, `sic_codes`, `exchanges`, `min_market_cap_usd`, `min_median_dollar_volume_usd`, `liquidity_sessions`, `rebalance` and `window`.
- `config/universe/us_small_mid.yaml` — the broad US small and mid-cap universe that H10's standalone use reads; its bounds equal the ones `config/hypotheses/h10.yaml` registered.

This file names their keys; their values are read from the files.

## Requirements

- <a id="RES-013"></a>**RES-013** — Each universe has exactly one rules file. The biotech universe is `config/universe/rules.yaml`, stored under `universe/{version}/`; any other universe is `config/universe/<universe_id>.yaml`, stored under `universe/<universe_id>/{version}/`. An all-digit universe id is refused, so it never collides with a version. An empty SIC list admits every SIC code and a market-cap ceiling is optional. No code names a universe: scripts and the portfolio run take the rules file as a parameter.
- <a id="RES-014"></a>**RES-014** — A rules file is pinned in MinIO under its version on that version's first build, and a different file under a built version is refused (`RulesVersionError`, HTTP 409 from the build endpoint). Changing a built universe means a new version, which is a new trial for every hypothesis that reads it.
- <a id="RES-015"></a>**RES-015** — A universe's rebalance date is the first NYSE session of the month, and a company is admitted only on data public before that session opens: share counts filed strictly before the rebalance date, closes strictly before the rebalance session, registrations filed before it. A period-end date is never a known-at date.
- <a id="RES-016"></a>**RES-016** — A member satisfies the rules file's SIC codes (by SEC's current code), its exchanges (an over-the-counter-only listing is not admitted), its market-cap floor and optional ceiling, and its liquidity floor. Market cap is the last share count filed before the rebalance date, restated through the splits after the count's date up to the price snapshot's `adjusted_through`, times the last close before the rebalance session. Liquidity is the median close × volume over the `liquidity_sessions` sessions before the rebalance session.
- <a id="RES-017"></a>**RES-017** — Listing spans come from filings: an exchange registration (`8-A12B`, `10-12B`) opens a span, and the first delisting notice or deregistration after it closes it; a company with a notice and no registration on record counts from its first filing; a notice for another class does not end a listed company; an inactive filer without a notice leaves at its last filing as `deregistered`; a relisting opens a new span. The exit reason is `acquired` when a change-of-control 8-K falls near the exit, otherwise `delisted` (Form 25) or `deregistered` (Form 15). Each member row carries `ticker_source`: `current` (SEC's ticker), `filing` (the symbol in its last inline XBRL report name, or before inline XBRL the XBRL instance named in its last report's filing index) or `unresolved`. Prices more than `_TRADING_AFTER_NOTICE` (`services/backtesting/src/auspex_backtesting/universe/builder.py`) after an exit belong to a reused symbol and are discarded.
- <a id="RES-018"></a>**RES-018** — A rule that cannot be evaluated does not exclude a company: with no price bars before the rebalance or no share count yet, its market cap or liquidity stays empty and it stays a member. A month whose market caps need a split history that is `unavailable` or does not reach the snapshot's `adjusted_through` is not written; the build lists it under `split_unavailable` and the next build retries it, and the month then equals a clean build.
- <a id="RES-019"></a>**RES-019** — The window comes from the rules file and ends at the last rebalance on or before today. The build refuses (HTTP 409) a `PRICE_HISTORY_START` later than the liquidity lookback before the window (`_PRICE_LOOKBACK` in `services/backtesting/src/auspex_backtesting/universe/job.py`), and refuses a month outside the window or after the build's `as_of`.
- <a id="RES-020"></a>**RES-020** — Monthly snapshots are written once and never overwritten (`SnapshotExistsError`); a build with every month stored downloads nothing. `listings.parquet` (every listing span as now known) and `coverage.json` are rewritten on every build, and backtests read exits and coverage from the latest `listings.parquet`, never from the month's snapshot. A rebuild over the same inputs gives the same months; a rerun after a later exit gives a different listings file.
- <a id="RES-021"></a>**RES-021** — Every build exports `backfill_scope.yaml`, the union of members from `BACKFILL_SCOPE_START` to the latest month, which the historical backfill reads.
- <a id="RES-022"></a>**RES-022** — The backtest universe is rules-based and pre-registered. Live ingestion scope (the watchlist) never defines it, and the watchlist never changes it.
- <a id="RES-023"></a>**RES-023** — Accepted limitations: classification uses SEC's current SIC code only (SEC publishes no history), and a renamed issuer carries its current ticker, under which price vendors file its whole history.
- <a id="RES-024"></a>**RES-024** — A member without complete price history stays in the snapshot with `price_coverage` `partial` or `none` and a `coverage_note`; `coverage.json` lists every such member with the reason. Excluding its events is a backtest rule ([backtesting.md](backtesting.md)), never a reason to drop the member.
- <a id="RES-025"></a>**RES-025** — The build reads SEC's two nightly bulk archives (filer submissions and XBRL company facts) instead of per-company requests. The per-company filing-index lookups for tickers before inline XBRL are paced under SEC's limit and stop for the run at the first refusal (403 or 429); the companies left are `unresolved` and counted, and a missing filing index leaves only that company unresolved.

## Known traps

- **Reruns differ.** `listings.parquet` and `coverage.json` are rewritten on every build (RES-020), so two backtests over the same months can read different exits after a later build. That is current behaviour, not a reproducibility guarantee; reproducibility comes from input manifests ([evaluation-protocol.md](evaluation-protocol.md#EVA-026)).
- **SEC keeps no ticker for an inactive filer,** and before inline XBRL (2019) the primary document is named by the filing agent. Tickers of members delisted in that period depend on the XBRL instance name (RES-017); unresolved members are counted, never dropped.
- **A late `PRICE_HISTORY_START` would silently remove the floors:** unknown values keep a company (RES-018), so without the check in RES-019 every early market cap would be unknown and every company admitted.
