# Evaluation protocol

Domain: EVA · Code: `services/backtesting/src/auspex_backtesting/hypothesis.py`, `services/backtesting/src/auspex_backtesting/protocol.py`, `services/backtesting/src/auspex_backtesting/evaluation/`, `services/backtesting/src/auspex_backtesting/portfolio/verdict.py`, `services/backtesting/scripts/register_hypothesis.py`, `services/backtesting/scripts/run_portfolio_backtest.py` · Last reviewed against: develop @ `b7582c3`

## Scope

How a hypothesis is registered, admitted, counted, evaluated and promoted: the hash lock on the protocol and hypothesis files, roles and statuses, the admission gate, the trial ledger and its durability, the event evaluation, variant reporting, the portfolio evaluation and its holdout, input manifests, and the forward check that gates capital.

Not in this file: what a backtest knows when and what it trades ([backtesting.md](backtesting.md)); costs and fills ([simulation.md](simulation.md)); the panels and scores hypotheses read ([panels.md](panels.md)); sizing and risk in the strategy runtime ([risk.md](../strategy/risk.md)); the dashboard's configuration pages ([dashboard.md](../dashboard.md)).

## Machine-readable authorities

- `config/hypotheses/protocol.yaml` — every value of the protocol, cited here by key only: `abnormal_return.*`, `inference.*`, `trials.*`, `families.*`, `portfolio_inference.*`, `promotion.*`, `sizing.*`, `instruments.*`, `forward_check.*`, `kill_criteria[*]`, `portfolio_kill_criteria[*]`.
- `config/hypotheses/h*.yaml` — each hypothesis: `evaluation`, `family`, `role`, `status`, `uses`, `trial_grid`, `trial_cells`, `primary_cell` and its evaluation-kind fields.
- `config/hypotheses/registry.jsonl` — one line per registered file version with its hash.

## Requirements

*Registration.*

- <a id="EVA-001"></a>**EVA-001** — The protocol and every hypothesis file are locked by a SHA-256 of their raw bytes recorded in `registry.jsonl` by `scripts/register_hypothesis.py`. A file whose bytes differ from its latest registration, or one never registered, is refused by every evaluation path until it is registered again; registering unchanged content is idempotent, and changed content is a new registry line.
- <a id="EVA-002"></a>**EVA-002** — Verification also checks a hypothesis's shape: `evaluation` is `event` or `portfolio` with a `role`; a portfolio hypothesis names no event-only field and has holdout years after its in-sample years; an event hypothesis names no portfolio-only field; `trial_cells` equals the product of `trial_grid`, which contains the primary cell.
- <a id="EVA-003"></a>**EVA-003** — There is one current protocol and one registered version per hypothesis. From the first evaluation on, the registry is append-only: a change is a new line, and earlier lines are never edited.
- <a id="EVA-004"></a>**EVA-004** — A hypothesis's trial family is the one it names (event hypotheses default to `default_event_family`), and each family has its own budget under `families`; a family not listed there has no budget and its hypotheses cannot be evaluated.
- <a id="EVA-005"></a>**EVA-005** — `instruments` holds ceilings: shorts and options are off unless the protocol enables them, and enabling one is a re-registration of the protocol, never an `.env` edit.
- <a id="EVA-006"></a>**EVA-006** — Research config is read-only outside the repository: hypotheses and `protocol.yaml`, the strategy registry, the model registry and gate records, and the universe rules are never written by a UI, runtime or API path. They change only through a dated re-registration or edit in the repository with a `DECISIONS.md` entry.

*Roles, status and admission.*

- <a id="EVA-007"></a>**EVA-007** — A `suspended` hypothesis is refused. Diagnostic and descriptive hypotheses are never counted against a budget or promoted; a filter's cells count but it is never promoted; a hypothesis with `uses` is validated, counted and promoted per use, and refused unless a use is named.
- <a id="EVA-008"></a>**EVA-008** — `EvaluationProtocol.admit()` runs before any evaluation reads returns and refuses a family with no registered budget, a family over budget once every registered hypothesis is counted, a role the family does not hold, and an instrument above the protocol's ceilings.
- <a id="EVA-009"></a>**EVA-009** — Every evaluation path, the raw-return `hypothesis.run_backtest` included, passes `admit()` and refuses a `suspended` hypothesis before it reads returns.
- <a id="EVA-010"></a>**EVA-010** — An event evaluation refuses, before anything is recorded: a modified protocol or hypothesis, a suspended hypothesis, a horizon, delay or variant outside the declared grid, and a missing `N_BOOTSTRAP`.

*Trial ledger.*

- <a id="EVA-011"></a>**EVA-011** — Trials are counted as cells across the hypothesis family. A run's cells are reserved in the family's ledger before it reads any return, the budget check and the reservation are one step under an exclusive lock, two runs cannot both take the last cells, and a run that fails later still counts. The raw-return backtest reserves its windows the same way, and the deflated Sharpe uses the family count after the run's own reservation.
- <a id="EVA-012"></a>**EVA-012** — A torn final ledger line (a write cut short) is dropped and counted nowhere; any other unreadable line stops every reservation until the file is fixed by hand.
- <a id="EVA-013"></a>**EVA-013** — An event run refuses a cell outside the hypothesis's registered `trial_grid`.
- <a id="EVA-014"></a>**EVA-014** — A portfolio run refuses a cell outside the hypothesis's registered `trial_grid`.
- <a id="EVA-015"></a>**EVA-015** — Applying the H10 biotech filter in a portfolio run reserves the filter use's cells in its family when the filter is applied.
- <a id="EVA-016"></a>**EVA-016** — The trial ledger and the holdout read records are durable and shared across every checkout and machine: a fresh clone can neither reset a family's count nor read a holdout again, and an event holdout read leaves a persistent record too.

*Event evaluation.*

- <a id="EVA-017"></a>**EVA-017** — An event's abnormal return is the market-model CAR against the protocol's benchmark, with the estimation window and minimum observations in `abnormal_return.*` (market-adjusted below the minimum, event and gap days excluded from estimation). Inference is two-way clustered by the dimensions in `inference.*`; below the minimum cluster count the t is clustered one way on the dimension with fewer clusters, with a wild cluster bootstrap p-value; overlapping same-ticker windows count as one independent event.
- <a id="EVA-018"></a>**EVA-018** — Horizon h is CAR[+1, +h] in sessions after an entry at `next_trading_day(corroborated_at + delay)`. In-sample is every event before the last `promotion.holdout_months` of the event range. The net return per event is the abnormal return minus the round-trip cost as a fraction of entry notional, with each trade's cost components reported. The deflated Sharpe is a probability, computed on per-observation net returns against the family trial count. `N_BOOTSTRAP` is read from `.env` and required.
- <a id="EVA-019"></a>**EVA-019** — An event result reports the primary cell, every cell, the kill verdicts of `kill_criteria` (thresholds read from the registered protocol), walk-forward segments and whether the holdout is sealed. Promotion is judged on the primary cell only, and a fired kill criterion blocks it.
- <a id="EVA-020"></a>**EVA-020** — The last `promotion.holdout_months` of an event range are not read during evaluation and are released only for a promotable result on the primary cell.
- <a id="EVA-021"></a>**EVA-021** — Walk-forward segments are a reported validation check, never an input to promotion.

*Variants.*

- <a id="EVA-022"></a>**EVA-022** — Every result built on corroborations reports the entity-only variant beside the full variant, each with its `variant` field, and a full-variant result is not interpreted before the leakage canary passes ([extraction.md](../ingestion/extraction.md)).

*Portfolio evaluation.*

- <a id="EVA-023"></a>**EVA-023** — A portfolio evaluation runs in this order: input manifests are checked, then whether the holdout was already read, then the cell is reserved once however many tiers run, then every capital tier is run over the in-sample years with a companion `top_quintile` run of the same rule, then the verdict is taken at the smallest tier, then on a final run that passed the holdout is read once. The report and the verdict are written side by side.
- <a id="EVA-024"></a>**EVA-024** — The portfolio verdict applies `portfolio_kill_criteria`, computes the deflated Sharpe on monthly net excess over the declared benchmark with the family trial count, and promotes only the primary cell of a promotable hypothesis; filters and diagnostics are not promotable.
- <a id="EVA-025"></a>**EVA-025** — A holdout is read once per hypothesis use: `HoldoutRecord` is created exclusively before the holdout years are read, and a second final run is refused.
- <a id="EVA-026"></a>**EVA-026** — An admissible result (a final run, a holdout read, a promotion) needs an input manifest for every universe and score snapshot it reads. Until manifests exist, every final run is refused before anything is reserved or read (`NoInputManifests`, `InputsNotPinnedError`), and builds made before then are disposable.

*Forward check and capital.*

- <a id="EVA-027"></a>**EVA-027** — `forward_check_branch()` gives the event or the portfolio branch by the hypothesis's evaluation kind. The portfolio branch is evaluated per capital tier on month-keyed paper and replay ledgers against the pass rule in `forward_check.*`; malformed inputs (non-finite values, a negative standard error, malformed, duplicated, shifted or missing months) give `invalid`, which is a data problem, not a kill.
- <a id="EVA-028"></a>**EVA-028** — No real capital goes into a strategy until its forward check passes at a capital tier, and that tier's result bounds how much.

## Known traps

- **The hash is over raw bytes** (`hypothesis.py`): a whitespace or comment edit to a registered file is a new registration and, after the first evaluation, a new trial.
- **Result-affecting parameters outside the registered files.** These change a result without touching `protocol.yaml` or `h*.yaml`, so a result names them beside its registration: the cost variables in `.env` ([simulation.md](simulation.md)); `N_BOOTSTRAP` in `.env`, beside `inference.bootstrap_draws` in the protocol; the walk-forward lengths (`WalkForwardSettings` in `services/backtesting/src/auspex_backtesting/protocol.py`); the delisting bound of −30% (`services/backtesting/src/auspex_backtesting/metrics/survivorship.py`, `DELISTING_TAIL_RETURN` in `services/backtesting/src/auspex_backtesting/portfolio/engine.py`); the 10% survivorship threshold in metrics; and the H10 period tolerance and score lookback (`services/backtesting/src/auspex_backtesting/filings/score.py`).
- **A strategy registry write path exists.** `StrategyRegistry._check_version` writes a `versions` directory under `config/strategies` when it is given `versions_dir` (`services/strategy/src/auspex_strategy/registry.py`); production passes none today, but the path contradicts [EVA-006](evaluation-protocol.md#EVA-006) if it is ever wired.

## Rationale

- **The portfolio forward check is an implementation check, not evidence.** Twelve monthly observations cannot establish a monthly portfolio's edge (`## 2026-10-07 — Edge research scoping — FLAG — paper trading cannot prove a monthly portfolio's edge in 12 months`, `DECISIONS.md`), so the statistical case comes from the in-sample backtest and the one holdout read, and the forward check confirms the implementation and data timeliness before capital (EVA-027, EVA-028).
