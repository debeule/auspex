# Market data

Domain: RES · Code: `services/backtesting/src/auspex_backtesting/prices/`, `services/backtesting/src/auspex_backtesting/api.py`, `services/backtesting/src/auspex_backtesting/stack_bootstrap.py` · Last reviewed against: develop @ `b7582c3`

## Scope

The price snapshots every backtest and the universe build read: where daily OHLCV bars come from, which bars are stored, how a snapshot grows, what its share basis is, the split histories stored beside it, and the price service's HTTP surface.

Not in this file: which DAG calls the endpoints and when ([orchestration.md](../operations/orchestration.md)); the metric catalogue of the price service ([observability.md](../operations/observability.md)); the universe built from these snapshots ([universe.md](universe.md)); the panels kept in the same bucket ([panels.md](panels.md)).

## Requirements

- <a id="RES-001"></a>**RES-001** — Each ticker has one OHLCV Parquet snapshot in the `auspex-prices` bucket, fetched from Yahoo, with Stooq as the fallback when Yahoo returns nothing. Delisted tickers come from the same free sources. A backtest reads the snapshot and never fetches prices itself.
- <a id="RES-002"></a>**RES-002** — The stack fills its own snapshots: on `up`, the `price-bootstrap` one-shot fills every missing snapshot and fails only when a ticker has no snapshot from any source; a snapshot it could not extend does not fail it. After that a daily refresh keeps the snapshots current.
- <a id="RES-003"></a>**RES-003** — A stored bar is never rewritten. A refresh only appends bars dated after the last stored bar, and a refresh with no new bar writes nothing. Rebuilding a snapshot is a deliberate delete and refetch, never a scheduled step.
- <a id="RES-004"></a>**RES-004** — Only settled bars are stored. A session bar is stored once its NYSE close, early closes included, plus the settle delay (`_SETTLE_DELAY` in `services/backtesting/src/auspex_backtesting/prices/price_refresher.py`) has passed, in UTC across daylight-saving changes. An FX bar, and a bar dated on a day that is not an NYSE session, settles that delay after its UTC day ends. An unfinished bar is dropped and fetched again by a later refresh.
- <a id="RES-005"></a>**RES-005** — A refresh appends only when its response repeats the last stored bar within the overlap tolerance (`_OVERLAP_TOLERANCE` in `services/backtesting/src/auspex_backtesting/prices/price_refresher.py`). A mismatch, or a non-empty response without that bar, raises `SnapshotDiscontinuityError` and writes nothing; the stored bars stay usable up to where they end. An empty response appends nothing and is not an error.
- <a id="RES-006"></a>**RES-006** — A snapshot's Parquet metadata records `adjusted_through`, the UTC date of its first download, and its closes are on that day's share basis. Market caps use splits only up to that date.
- <a id="RES-007"></a>**RES-007** — Each ticker's split history is stored once beside its prices as `available`, `confirmed_empty` (the provider answered with no splits) or `unavailable` (the lookup failed, nothing stored), and vouches for splits only up to its `covered_through` date. A read beyond `covered_through` fetches again; a failed refetch is `unavailable`, never the stored history. `unavailable` is never read as "no splits".
- <a id="RES-008"></a>**RES-008** — Every refresh covers the protocol's benchmark ticker and the EUR/USD pair, each once, beside the configured tickers (`price_universe` in `services/backtesting/src/auspex_backtesting/prices/price_refresher.py` names them).
- <a id="RES-009"></a>**RES-009** — A missing snapshot is first fetched from `PRICE_HISTORY_START` (its value lives in `.env.example`). The schedule never extends a stored snapshot backwards.
- <a id="RES-010"></a>**RES-010** — Every snapshot, however it is written, carries `adjusted_through` and holds settled bars only.
- <a id="RES-011"></a>**RES-011** — The price service exposes `POST /prices/refresh` and `POST /universe/build`. A refresh without a body refreshes the configured tickers, a body can narrow them, and one failing ticker fails the request (HTTP 502) while the rest still refresh. A universe build answers with its summary, 409 on a configuration conflict (edited rules under a built version, a price history that starts too late) and 502 when a source is unreachable.
- <a id="RES-012"></a>**RES-012** — The price service exposes `GET /health`, which answers `{"status": "ok"}` while the service runs.

## Known traps

Sources: requirements §8; [`services/backtesting/README.md`].

- **yfinance is unofficial and rate-limited.** It scrapes Yahoo under personal-use terms, and a `YFRateLimitError` can block a host for hours. Fetching each bar once (RES-001, RES-003) is what keeps the stack inside the limit; do not add retries that refetch history.
- **Yahoo's `auto_adjust` also adjusts for dividends,** not only splits, so a snapshot's closes are total-return-adjusted to `adjusted_through` (RES-006). Do not mix them with unadjusted closes from another source.
- **Stooq uses its own symbols** (a market suffix, its own class notation). The fallback passes the ticker as it is, so a symbol Stooq writes differently returns nothing and the ticker counts as having no data.
