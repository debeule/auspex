## Scope

Everything between a connector yielding a document and Kafka acknowledging what the run published: the stage order, the MinIO archive and its object key, deduplication and precedence, the pre-filter, the normalizer seam, the extraction cap, the run result and the cursor it returns, delivery confirmation, and the scraper HTTP API.

The scraper writes only MinIO and Kafka (INV-1); the archive write is unconditional and first (INV-13). The raw pointer and the signal event the pipeline publishes are contracts, CON-005 to CON-006 and CON-008, and the identities they carry are CON-018 and CON-019; no field list is repeated here.

`services/ingestion-scraper/scripts/run_pipeline.py` runs the pipeline without Airflow as a developer tool. It carries no requirement (`2026-10-17 — Living docs — CHOICE — run_pipeline.py support`, answering `2026-10-15 — Living docs — PENDING — run_pipeline.py support`).

Not in this file:
- what a connector yields and when a document was public: [connectors.md](connectors.md);
- the model call, the publish threshold, prompt versions, the gate and re-extraction: [extraction.md](extraction.md);
- the DAG side of the cursor (reading and saving the Airflow Variable, failing the task after saving, Fernet), schedules, the pool, retries and timeouts: [orchestration.md](../operations/orchestration.md);
- metric names, metric-registration traps, alerts, and the log contract every log line follows: [observability.md](../operations/observability.md).

## Requirements

- <a id="ING-022"></a>**ING-022** — For each document the stages run in this order: archive; raw pointer (CON-006); unchanged re-fetch check; cross-source canonical check; pre-filter; extraction cap; extract; publish threshold; normalize; publish. The archive write comes before every other side effect (applies INV-13), and a document whose archive object already exists stops after the archive.
- <a id="ING-023"></a>**ING-023** — `IngestionPipeline` is the single caller of the connector, the archive, the extractor and the producer.
- <a id="ING-024"></a>**ING-024** — A document that fails at any stage is counted in `failed` and the run continues with the next document.
- <a id="ING-025"></a>**ING-025** — `RunResult` holds, per run: `fetched` (documents the connector yielded); `prefiltered_out` (documents rejected by the pre-filter, plus documents skipped because their archive object already existed, because a processed marker matched, or because another source's canonical marker exists); `not_signal`; `below_threshold`; `published` (signal events handed to the producer); `failed` (failed documents, plus one when the end-of-run flush fails); `max_published_date_processed` (the latest `published_date` among archived documents); `next_cursor` (ING-026); and `capped` (the run stopped at the extraction cap).
- <a id="ING-026"></a>**ING-026** — The pipeline is stateless with respect to cursors: `run(source_type, cursor)` takes the cursor and returns `next_cursor`, which is the input cursor when the run stopped at the extraction cap or delivery was not confirmed; else the earliest `published_date` among failed documents; else the latest processed `published_date`. It never reads or writes cursor state; the DAG side is in [orchestration.md](../operations/orchestration.md).
- <a id="ING-027"></a>**ING-027** — A run sends at most the `max_documents_per_run` of its source entry to extraction; documents skipped as already processed do not count toward it.
- <a id="ING-028"></a>**ING-028** — `POST /ingest/<source_type>` refuses a second concurrent run of the same source with 409, and a run of one source never waits on a run of another.
- <a id="ING-029"></a>**ING-029** — Publishing is not fire-and-forget: the run flushes the producer and checks delivery reports, and a message that was not delivered fails the run.
- <a id="ING-030"></a>**ING-030** — The archive object key is `raw/{source_type}/{external_id}/{retrieved_at:%Y%m%dT%H%M%SZ}-{content_sha256[:8]}.json`, with `retrieved_at` in UTC (applies INV-9). A re-fetch of identical content within the same second is a no-op, not an error.
- <a id="ING-031"></a>**ING-031** — Deduplication gates extraction and publish only, never the archive.
- <a id="ING-032"></a>**ING-032** — A processed marker under `dedup/processed/` is written for a document only after its outcome is final (published, not a signal, or below the threshold) and the run's flush succeeded. It is keyed on the content hash and on the extraction identity `model|prompt_version|prefilter_version`. A re-fetch with a matching marker skips extraction and publish.
- <a id="ING-033"></a>**ING-033** — An amendment, the same document with a different content hash, is extracted and published under the same `event_id` with a new `extraction_id` (CON-018, CON-019).
- <a id="ING-034"></a>**ING-034** — A cross-source canonical marker, `dedup/canonical/{sha256(canonical_id)}.json` naming the source that published first, is written only after that document's signal was delivered. A failed marker write costs at most one repeat extraction, which consumers absorb as an idempotent write.
- <a id="ING-035"></a>**ING-035** — A later fetch of a `canonical_id` whose marker names another source skips extraction and records that source's observation of the event.
- <a id="ING-036"></a>**ING-036** — Without a `canonical_id`, cross-source duplicates are accepted.
- <a id="ING-037"></a>**ING-037** — A deterministic vocabulary pre-filter runs before every model call: a document passes when its `raw_content`, which carries the title and body alike, contains at least one term of its entry's `prefilter_vocabulary`, case-insensitively, and an empty vocabulary passes everything. Rejected documents are counted.
- <a id="ING-038"></a>**ING-038** — Every extracted event's gene targets and company names pass through the `EntityNormalizer` seam before publish; production wires the identity implementation.
- <a id="ING-039"></a>**ING-039** — The scraper HTTP API (applies INV-3): `GET /health`; `GET /sources` lists the configured source types; `POST /ingest/<source_type>` returns the run's `RunResult` as JSON, 404 for a source with no `sources.yaml` entry and 500 with the error text when the run raises, and a body without a cursor starts at ING-004; `POST /reextract` ([extraction.md](extraction.md)); `GET /metrics` in Prometheus text format.
- <a id="ING-040"></a>**ING-040** — Each run logs one summary with its `RunResult` counts and the cursor before and after. The format of that line is set by the log contract in [observability.md](../operations/observability.md).

## Known traps

Sources: `CLAUDE.md:205` (Known traps); `services/ingestion-scraper/CLAUDE.md:33`.

- **`confluent-kafka`'s `produce()` is asynchronous.** A run that never calls `flush()`, or ignores the delivery reports, can report success and have published nothing. Protects ING-029, ING-032 and ING-034.
- **`strftime` on an aware datetime that is not in UTC writes local wall time**, and a literal `Z` after it then lies. The object key converts `retrieved_at` to UTC before formatting, which `RawDocument` does on construction. Protects ING-030.

## Rationale

Non-normative.

- **The stage order.** Requirements §6.2 listed "pre-filter, dedup, MinIO archive, extract, publish". That order was stale: §7, §7.1 and INV-13 put the archive first and unconditional, and the code has always archived first. ING-022 is the order as built, with the raw pointer right after the archive (`specs/done/raw-pointer-contract-fix.md`).
- **The pre-filter's cost case** (requirements §6.6). Most fetched EDGAR and openFDA documents are irrelevant and extraction is the dominant cost; counting rejections keeps an over-aggressive vocabulary visible. Its false negatives are measured on the golden set ([extraction.md](extraction.md)).
- **Why dedup never gates the archive** (requirements §7.1). A document archived but never published, during a Kafka outage, stays recoverable; dedup keyed on the fetch would make it invisible.
- **The canonical marker after publish** (requirements §7.1). Writing it first could suppress a document that never published; writing it after costs at most one repeat extraction.
- **No embedding-similarity dedup** (requirements §7.1). It would need a vector store and an embedding call per document to solve what a DOI solves.
- **Scope by vocabulary.** `2026-08-15 — Step 0.0 — CHOICE — Ticker-restricted ingestion via pre-filter vocabulary (no architecture change)` set the ingestion scope through the pre-filter vocabulary; the vocabulary now lives per entry in `services/ingestion-scraper/config/sources.yaml`.
- **The extraction cap** is sized so a capped run fits the DAG task timeout (`services/ingestion-scraper/config/sources.yaml`, header comment); the timeout itself is in [orchestration.md](../operations/orchestration.md).
