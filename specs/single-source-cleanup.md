# Single-Source Cleanup

**Status:** ready
**Branch:** `feature/single-source-cleanup`

---

## Context

Nothing has rolled out: no extraction has run, no backtest has used a hypothesis or strategy, no event has been published. The owner wants one source of truth for every spec, protocol, config, prompt, schema and doc, edited in place until something real has used it. An audit on 2026-10-09 found versions and copies that exist only because a file was revised before first use. This spec removes the ones on `develop`.

Each item below names where the duplicate lives today:

1. **Extraction prompts.** `services/ingestion-scraper/prompts/extraction/` holds `v1.txt`, `v1.0.txt` (byte-identical to `v1.txt`) and `v1.1.txt`. Only `v1.1` is used: `_DEFAULT_PROMPT_VERSION` in `auspex_ingest/extraction_backend.py`, `EXTRACTION_PROMPT_VERSION` in `.env.example`, and a repeated `"v1.1"` literal as the argparse default in `scripts/evaluate_model.py`, `compare_models.py`, `score_extraction.py` and the help text of `reextract.py`. Unit tests pass `"v1.0"` and `"v1"` strings.
2. **Gate record and prefilter.** `config/models/scores/gpt-4o-mini-2024-07-18.json` is a hand-written gate record (DECISIONS.md 2026-09-19 entries) for prompt `v1.0` and prefilter `v1.0`. The service already refuses it, because production runs prompt `v1.1` and prefilter `PREFILTER_VERSION = "v1"` (`auspex_ingest/prefilter.py`). `services/ingestion-scraper/config/prefilter/v1.yaml` (`version: "1"`) is read by no code: the live vocabularies are the `prefilter_vocabulary` lists in `config/sources.yaml`. `specs/golden-set-expansion.md` says the record was "produced"; `specs/managed-ingestion-config.md` carries a note about its `v1.0` mismatch.
3. **Event schema.** `EVENT_SCHEMA_VERSION = "1.1"` (`auspex_ingest/models.py`). `docs/requirements.md` §10.2 lists the fields in two tiers and says "Consumers treat them as absent on 1.0 events", but no 1.0 event was ever produced. Java carries the same split: `ResearchSignalEvent` Javadoc says the fields "arrived in schema 1.1", and `TestFixtures` keeps a 1.0 base event plus a 1.1 variant made by string replacement. The contract fixture `services/core-hub/src/test/resources/contract/signal_event_v1.json` is generated by `tests/unit/test_contract_fixture.py`. Flyway `V4__company_level_fields.sql` also says "schema 1.1" in its header, but applied migrations are frozen.
4. **Legacy extractor.** `auspex_ingest/extractor.py` keeps `LLMExtractor` beside `BackendLLMExtractor` (`extraction_backend.py`). Production (`api.py`) and every script use the backend. Only `tests/unit/test_company_level_extraction.py` (the "legacy extractor" test) and `tests/unit/test_scoring.py` construct it. The module also holds the shared `EventType`, `_ExtractionResult`, `resolve_trial_ids` and `_MAX_CONTENT_CHARS`, which the backend and tests import.
5. **Superseded DAG design.** `orchestration/README.md` describes one DAG per source generated by `dag_factory.py`, with each task calling `IngestionPipeline.run()`, and names `orchestration/airflow/dags/auspex_dags.py` as the entry point. That directory holds only `.gitkeep` files. The real DAG is `services/ingestion-scraper/dags/auspex_dags.py`, which calls the scraper HTTP API (Invariant 3), and compose mounts it. In `auspex_ingest/dag_factory.py`, `build_dags` and `run_with_cursor` are used only by `tests/unit/test_dag_factory.py`. `load_sources_config` is live (`api.py`, `scripts/run_pipeline.py`).
6. **Superseded plan.** `docs/plan.md` is kept as "reference only, superseded by `specs/`". Every phase 4 to 6 step has its own spec, done or active, and phases 0 to 3 are in `docs/HISTORY.md`. Its paths are stale (`prompts/extraction/v1.md`, `config/prefilter/`). It is cited by `CLAUDE.md` (always-loaded list and file map), `docs/requirements.md` (the opening note and the "plan.md instruction 4" line), `docs/strategy-research.md` ("Per `docs/plan.md` §4.2") and `specs/historical-backfill.md` ("Carried from plan.md Step 4.0"). `docs/requirements.md` also gives the prompt path as `prompts/extraction/v{N}.md`; the files are `.txt`.
7. **Strategy parameter copies.** Each `config/strategies/<name>.yaml` repeats `holding_period_days` and `entry_timing_days` from its `config/hypotheses/h*.yaml`. `source_composition.yaml` declares one `source_type_pair` where `h5.yaml` registers seven. `confidence_gradient.yaml` has `min_confidence_score: 0.7`, while `h7.yaml` registers an above vs below median split. No strategy reads its parameters file: the registry only hashes it for `VersionConflictError`. `negative_asymmetry` (strategy, stub module, params file and registry entry) implements the short H8 design that `h8.yaml` suspended ("not a short strategy").
8. **Stale hold spec.** `specs/hold/watchlist-alerts.md` keeps a "schema section is stale" banner next to the superseded `watchlist_entries` DDL and tests that query it. The watchlist tables are `watchlist` and `watchlist_gene_target` (Flyway V3). The corroboration entity key is `<normalised name>:<label>` (`CorroborationScanner.java`), so the banner's open question about a ` | ` separator is already answered.
9. **Compose defaults repeated from `.env.example`.** `docker/docker-compose.yml` repeats `.env.example` values as `${VAR:-value}` defaults for `AIRFLOW_DB_USER`, `PRICE_HISTORY_START`, `BACKFILL_SCOPE_START`, `NEO4J_USER`, `SCRAPER_API_URL`, `PRICE_API_URL` and `DASHBOARD_PORT`. `services/backtesting/tests/unit/test_universe_build.py::test_default_price_history_reaches_before_the_universe_window` reads both copies.

## What this builds

One version of each item, with a test that fails if a second one comes back:

1. One extraction prompt, `prompts/extraction/v1.txt`, holding today's `v1.1` text. The service default, `.env.example`, the scripts and the docs all name `v1`. The scripts import the service default instead of repeating a literal.
2. No committed gate record until a real gate run writes one (the scores directory stays, with a `.gitkeep`). `config/prefilter/` is deleted, so `sources.yaml` is the only vocabulary source. The prefilter version is spelled `v1` everywhere it is written, including test data.
3. One event schema, version `1.0`, with one field list in requirements §10.2. The scraper stamps `1.0`. Java requires `event_type`, `program_identifiers` and `trial_ids` like every other non-null field (only `primary_company` stays nullable), has one test event that carries every field, and its Javadoc no longer mentions a 1.1. The contract fixture is regenerated by its pytest, not edited by hand.
4. One extractor, `BackendLLMExtractor`. `LLMExtractor` is deleted. The behaviours its tests covered are tested on the backend extractor wherever they are not already covered.
5. One description of ingestion scheduling. `orchestration/README.md` describes the DAG that calls `/ingest/<source_type>` and points at `services/ingestion-scraper/dags/auspex_dags.py`. `build_dags`, `run_with_cursor` and `dag_factory.py` are deleted. `load_sources_config` moves to `auspex_ingest/sources.py`. The empty `orchestration/airflow/` placeholders are removed.
6. No `docs/plan.md`. Every reference to it points at the spec, requirement section or `docs/HISTORY.md` entry that holds the content now. The requirements prompt path reads `prompts/extraction/<version>.txt`.
7. Hypothesis files are the only place hypothesis parameters live. A strategy parameters file holds only knobs its hypothesis does not register. Today none are left, so the files are deleted and `parameters_file` becomes optional in `config/strategies/registry.yaml`. A strategy without one versions on its code hash alone. The `negative_asymmetry` strategy is removed. The `confidence_gradient` description says median split.
8. `specs/hold/watchlist-alerts.md` specifies storage against `watchlist JOIN watchlist_gene_target` with the colon entity key, without the banner and without the old DDL. It stays on hold.
9. Each `.env.example` value lives only in `.env.example`. Compose references those variables as a bare `${VAR}`, the convention infrastructure observability set for the monitoring variables (DECISIONS.md 2026-10-09, "monitoring values only in .env.example"). An `.env` copied before a variable existed gains it from step 1 of `specs/first-run-on-stack-machine.md`.

## Constraints

- **Invariant 3:** the DAG keeps calling the HTTP API. Deleting `dag_factory` must not move pipeline logic anywhere near a DAG.
- **Invariant 6:** compose keeps reading values from `.env`. Removing the `:-` default only removes the hidden copy.
- **Invariant 7:** the Python model and Java record stay field-for-field identical. The contract fixture is regenerated by pytest, never hand-edited.
- **Invariant 14:** `event_id` does not depend on the schema version. `extraction_id` does, and it changes from `1.1` to `1.0`. No extraction exists yet, so nothing stored changes.
- **Flyway migrations are frozen:** do not touch `V*__*.sql`.
- **Tests read real repo files** where the claim is about the repo (prompt directory, scores directory, compose, `.env.example`, strategy and hypothesis configs), the way `test_universe_build.py` and `test_strategy_framework.py` already do.
- Update every README and CLAUDE.md the CLAUDE.md doc table maps to these changes: the scraper README (prompts, scripts, configuration), `docker/README.md` and `docker/CLAUDE.md` (the compose rule), `orchestration/README.md`, `services/strategy` docs if present, `docs/local-model-runbook.md`, `SETUP.md`, `specs/first-run-on-stack-machine.md`, `specs/golden-set-expansion.md` and `specs/managed-ingestion-config.md` (prompt and gate wording), and root `CLAUDE.md` (plan.md references).

## Notes

- **Why `v1` and not `v1.1` for the prompt name.** A version number that implies earlier versions misleads the next reader. The first gate run on the stack machine will write the first real gate record at `v1`.
- **Why the schema resets to `1.0` while the V4 header says 1.1.** Migrations are frozen. The header is a comment in a file Flyway checksums, and DECISIONS.md records why it disagrees.
- **Why bare `${VAR}` and not `${VAR:?…}`.** `:?` would stop `up` on a stale `.env`, but the monitoring variables already merged as bare placeholders, with the first-run preflight adding missing keys. Two spellings for the same rule would be the duplication this spec removes.
- **`docs/HISTORY.md` stays.** It records what happened, not a parallel version of anything current. Its `dag_factory` lines describe phase 2 and are excluded from the grep, as are this spec and the test that asserts the module is gone.
- Record one `DECISIONS.md` CHOICE entry: "Single-source cleanup — CHOICE — one version of each pre-rollout artifact". List what was collapsed and the V4 header note.
