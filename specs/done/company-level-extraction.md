# Company-Level Event Extraction

**Status:** done
**Branch:** `feature/company-level-extraction`

---

## Context

Corroboration today links two documents that share a `GeneTarget` or `Mechanism` (requirements §4, §9). Most such matches are academic or registry activity with no mapping to the company whose stock would move. The 2026-10-07 edge feasibility audit rates the event definition as fatal for trading and recommends (rows 4 and 6):

- linking each event to a company and program through identifiers: the trial sponsor, NCT IDs, drug development codes such as `SRP-9001`;
- classifying each event into a typed taxonomy (readout, CRL, approval, clinical hold, trial halted, and so on), because published event studies measure returns per event type.

Extraction is the only place these can come from, and the schema must change before the historical backfill runs; afterwards every archived document would need a re-extraction pass on the local model.

What exists:
- `ResearchSignalEvent` in `services/ingestion-scraper/src/auspex_ingest/models.py` and its Java twin `dev.auspex.corehub.signal.ResearchSignalEvent`. The contract fixture `services/core-hub/src/test/resources/contract/signal_event_v1.json` is generated by `tests/unit/test_contract_fixture.py`.
- The LLM response model `_ExtractionResult` in `extractor.py`, used by `BackendLLMExtractor` in `extraction_backend.py`.
- Versioned prompts in `prompts/extraction/`; production reads `EXTRACTION_PROMPT_VERSION` (default `v1.0`). A model is only usable with a passing gate record for the exact prompt version (`config/models/scores/`).
- `ClinicalTrialsConnector._map` builds `raw_content` from title, brief summary, NCT ID and status. It does not include the lead sponsor.
- `SecEdgarConnector` already writes `Entity: <filer name>` into `raw_content`.
- `core-hub` persists events to `signal_current` (Flyway `V1`), `signal_extraction_history` and `source_observation`, and to Neo4j.

## What this builds

Schema `1.1` of `ResearchSignalEvent`, an additive minor bump, with four new fields:

| Field | Type | Meaning |
|---|---|---|
| `event_type` | string, closed set | What happened. One of `trial_readout`, `trial_initiation`, `trial_halted`, `trial_revised`, `clinical_hold`, `regulatory_submission`, `regulatory_designation`, `regulatory_approval`, `complete_response_letter`, `preclinical_data`, `patent_publication`, `other`. |
| `primary_company` | string or null | The company whose program the event concerns (trial sponsor, filer, applicant, developer). Null for purely academic work. |
| `program_identifiers` | list of strings | Drug development codes and drug names the event concerns (`SRP-9001`, `delandistrogene moxeparvovec`). |
| `trial_ids` | list of strings | ClinicalTrials.gov NCT IDs the event concerns, validated as `NCT` + 8 digits. |

Direction stays in `directionality`: a positive readout is `event_type=trial_readout` with `directionality=positive`.

Concretely:
1. Prompt `v1.1` asks for the four fields; `_ExtractionResult` carries them. `v1.1` becomes the production default.
2. The extractor normalizes the output: unknown `event_type` values become `other`; NCT IDs are upper-cased, invalid ones dropped, and a document whose `canonical_id` is `nct:<id>` always lists that trial.
3. The CT.gov connector adds `Lead sponsor: <name>` to `raw_content`.
4. The Python model, the Java record and the regenerated contract fixture carry the fields; events are stamped `schema_version` `1.1` from one constant.
5. `core-hub` accepts `1.0` events without the fields (minor-version tolerance) and persists the fields to `signal_current` (Flyway `V4`), so the backfill keeps them for the later corroboration work without a re-extraction.
6. `golden.score_batch` scores the new fields on golden documents that carry labels for them, and `score_extraction.py` reports them.

## Out of scope

- Any change to corroboration, the Neo4j graph model, or `CorroborationService` (the company-program corroboration is its own spec).
- Ticker resolution (`primary_company` or CIK to ticker via `SecTickerCache`).
- Changing which documents count as signals. Financing events stay `is_signal=false`; offerings arrive with their own connectors.
- Labelling the golden set for the new fields, and running the gate. The gate runs on the backfill machine.
- The EDGAR connector (8-K exhibit work is a separate change).

## Constraints

- Invariant 7: Python model and Java record field-for-field identical, snake_case on the wire, fixture generated by pytest.
- Invariant 14: `event_id` never varies with schema or prompt version. `extraction_id` changes with `prompt_version`, as designed.
- Invariant 4: no `if source_type == ...` in shared code. The NCT rule keys on the typed `canonical_id` prefix, not the source.
- Requirements §10.4: a minor bump must be accepted by consumers on the old minor and vice versa. New Java components are nullable; persistence writes empty arrays for missing lists.
- Requirements §11.2: extracted identifiers are untrusted output and are validated before they leave the extractor.
- Requirements §11.3: the prompt is a new versioned file; `v1.0` stays byte-identical so existing gate records keep their meaning.
